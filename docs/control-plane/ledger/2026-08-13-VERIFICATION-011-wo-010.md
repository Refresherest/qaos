## Architectural boundary achieved

Storage construction is now explicit via `create_stores(data_dir) -> Stores`, replacing the module-level `*_db = JSONStore(...)` singletons in `src/qaos/storage/database.py` as the active ownership mechanism.

- `create_stores(data_dir)` constructs a `Stores` collection of eight `JSONStore` instances bound to the supplied `data_dir`.
- `Stores` exposes `memory_db`, `knowledge_db`, `artifact_db`, `objective_db`, `reflection_db`, `event_db`, `plan_db`, `queue_db`.
- Module-level `*_db` singletons were removed from `database.py` and are no longer re-exported from `qaos.storage`.
- The seven domain managers now construct storage explicitly: each `__init__(self, stores=None)` uses `stores or create_stores(DATA)`, preserving prior behavior (default data directory) while allowing an explicit collection to be supplied.

## planner/plan_db.py resolution

`src/qaos/planner/plan_db.py` was the additional direct construction path named by WO-009/VERIFICATION-010. It imported `JSONStore, DATA_DIR` from `qaos.planner`, but `qaos.planner.__init__` never exported those names, so the module raised `ImportError` on import. No code imported it (`planner/manager.py` imports `from qaos.storage import plan_db`). It was dead and broken. It was removed; the active plan store is now `Stores.plan_db` via `create_stores`.

## queue/queue_db.py assessment (not changed)

`src/qaos/queue/queue_db.py` imports `from .json_database import JsonDatabase`, but `json_database.py` does not exist anywhere in `src/`. It raises `ModuleNotFoundError` on import and is imported by nothing (`queue/manager.py` uses `qaos.storage.queue_db`). It is pre-existing dead/broken code at baseline `9bcbfd3`, untouched by this work order. It is NOT named in WO-010 scope, so it was left in place to avoid broadening the work order. A full `pkgutil.walk_packages` sweep fails on this module; this failure is pre-existing and not a WO-010 regression. Removing it requires a separate work order.
