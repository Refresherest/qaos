# VERIFICATION-082 — WO-089 Task Identity Recovery Precondition

## Reviewer Outcome

`ACCEPT WITH NOTES`

## Evidence Verified

- PlannerManager and QueueManager deserialize separate Task objects.
- Queue action reset does not update the reloaded Plan Task.
- Neither persisted copy has canonical Task identity.
- Objective ID cannot select one Task within an attempt.
- FINDING-037 directly blocks coherent durable recovery.
- PROPOSAL-009 rejects live-process-only and inferred-correlation shortcuts.
- Option A keeps Plan as canonical Task owner and extends manager-owned opaque
  identity without provider coupling.

## Note

The exact moment PlannerManager assigns IDs to newly added Tasks requires
focused implementation design, but must occur before persistence or queueing.
Recovery implementation remains blocked until the owner selects and the PE
implements a Task identity contract.

- Probe data: isolated and removed
